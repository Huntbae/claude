# Voicebox 기술 검토 보고서

- 검토 대상: [jamiepine/voicebox](https://github.com/jamiepine/voicebox) v0.5.0 이후 main 브랜치, 커밋 `ee49508` (2026-10-04)
- 검토일: 2026-10-05
- 검토 범위: 기능, 구조, 한국어 지원, 라이선스, 법적 위험, 도입 방안
- 검증 방법: 소스 코드 직접 확인, 업스트림 백엔드 서버를 실제로 띄워 REST API와 MCP 서버 호출 검증

## 1. 요약

| 항목 | 판단 |
|---|---|
| 한 줄 정의 | 음성 합성(ElevenLabs 대체)과 받아쓰기(WisprFlow 대체)를 내 PC에서 처리하는 무료 오픈소스 음성 스튜디오 |
| 도입 권고 | 조건부 권고. 본인 음성 또는 동의받은 음성, 그리고 프리셋 음성으로 내레이션 초안을 만드는 용도에 적합 |
| 주요 장점 | 사용료 없음, 데이터가 외부로 나가지 않음, REST API와 MCP로 자동화하기 쉬움 |
| 주요 제약 | 한국어 지원 엔진은 3종뿐이고, 한국어 품질은 아직 검증되지 않음. GPU가 없으면 생성 속도가 느림. 0.x 버전이라 API가 바뀔 수 있음 |
| 필수 조치 | 화자 동의서 확보, AI 생성 표시, 업스트림 버전 고정 |

## 2. 구조

```
[데스크톱 앱 (Tauri/Rust) 또는 웹 UI]
          │
          ▼
[FastAPI 백엔드 :17493] ── REST API (/generate, /profiles, /speak, ...)
          │              └─ MCP 서버 (/mcp/) ── Claude Code, Cursor 등
          ▼
[TTS 엔진 7종] [Whisper 받아쓰기] [로컬 LLM (Qwen3)]
          │
          ▼
[Hugging Face에서 처음 쓸 때 모델 자동 다운로드 → 로컬 캐시]
```

예를 들면, 식당 주방(백엔드)이 하나 있고 손님은 홀(데스크톱 앱)로 들어오든 배달 앱(REST API)으로 주문하든 같은 주방에서 같은 음식을 받습니다. 이 저장소의 `voicebox_kr.py`는 배달 앱 쪽 주문 창구에 해당합니다.

## 3. 한국어 지원 현황

코드(`backend/backends/__init__.py`의 모델별 언어 목록)에서 확인한 결과입니다.

| 엔진 | 방식 | 한국어 | 비고 |
|---|---|---|---|
| Qwen3-TTS (1.7B / 0.6B) | 음성 복제 | 지원 | 말투 지시(`instruct`) 가능 |
| Qwen CustomVoice (1.7B / 0.6B) | 프리셋 음성 | 지원 | 한국어 여성 화자 `Sohee` 내장. 참조 음성이 필요 없음 |
| Chatterbox Multilingual | 음성 복제 | 지원 | 23개 언어 |
| Chatterbox Turbo | 음성 복제 | 미지원 | 영어 전용 |
| HumeAI TADA (1B / 3B) | 음성 복제 | 미지원 | 3B 다국어 모델도 한국어는 없음 |
| Kokoro | 프리셋 음성 | 미지원 | 8개 언어에 한국어 없음 |
| LuxTTS | 음성 복제 | 미지원 | 영어 전용 |

받아쓰기는 Whisper 기반이므로 한국어 인식이 가능합니다.

품질은 확인하지 않았습니다. 이 검토 환경에서는 Hugging Face 접속이 차단되어 모델을 내려받을 수 없었기 때문에, 실제 음성 품질 청취 평가는 사용자 PC에서 진행해야 합니다(5장 참조).

## 4. 실제 검증 결과

업스트림 백엔드(커밋 `ee49508`)를 CPU 환경에서 실행하고 이 저장소의 클라이언트로 호출했습니다.

| 검증 항목 | 결과 |
|---|---|
| `/health` 서버 상태 조회 | 성공 |
| 한국어 프리셋 프로필(소희) 생성, 중복 생성 방지 | 성공 |
| 프리셋 화자 목록에서 한국어 화자 식별 | 성공 |
| 참조 음성 업로드로 복제 프로필 생성 | 성공 |
| 잘못된 음성 파일 업로드 시 빈 프로필 자동 정리 | 성공 |
| `/generate` 요청, 상태 폴링, 실패 사유 보고 | 성공. 단, 모델이 없어 생성 자체는 예상대로 실패 |
| MCP 서버 도구 목록, 프로필 조회 호출 | 성공. 도구 이름은 `voicebox_speak`, `voicebox_transcribe`, `voicebox_list_profiles`, `voicebox_list_captures` |
| 실제 음성 품질 | 미검증 (모델 다운로드 불가) |

참고 사항:
- 업스트림 README는 MCP 도구 이름을 `voicebox.speak`처럼 점(.)으로 표기하지만, 실제 서버는 밑줄(`voicebox_speak`)을 씁니다.
- 업스트림 README의 `claude mcp add voicebox --transport http --url ...` 명령은 현재 Claude Code CLI에 `--url` 옵션이 없어 동작하지 않습니다. 올바른 형식은 `claude mcp add --transport http voicebox <URL> --header ...` 이며, 이 형식으로 생성한 설정 파일이 `mcp/claude-code.mcp.json`과 일치함을 확인했습니다.
- `/mcp`로 요청하면 `/mcp/`로 리디렉션(307)됩니다. 리디렉션을 따라가지 않는 클라이언트를 고려해 설정 예시에는 `/mcp/`를 사용했습니다.

## 5. 다른 서비스와 비교

| 항목 | Voicebox | ElevenLabs | HeyGen |
|---|---|---|---|
| 비용 | 무료(전기료와 하드웨어 비용만) | 월 구독 및 사용량 과금 | 월 구독 및 크레딧 |
| 데이터 위치 | 내 PC | 클라우드 | 클라우드 |
| 한국어 음성 품질 | 미검증 | 상용 수준 | 상용 수준 |
| 영상(아바타) | 없음 | 없음 | 있음 |
| 자동화 | REST, MCP | REST | REST, MCP |
| 속도 | 하드웨어에 따라 다름 | 빠름 | 빠름 |

요금은 수시로 바뀌므로 이 보고서에 금액을 적지 않았습니다. 도입 전에 각 서비스 요금표를 직접 확인하기 바랍니다.

권장 품질 평가 방법: 같은 대본 3문단(약 1분)을 Voicebox(소희 프리셋, 본인 음성 복제), ElevenLabs, HeyGen으로 각각 생성한 뒤, 발음 정확도, 억양 자연스러움, 숫자와 영어 약어 읽기, 잡음을 5점 척도로 비교합니다.

## 6. 라이선스

| 대상 | 라이선스 | 상태 |
|---|---|---|
| Voicebox 소스 코드 | MIT (상업적 이용, 수정, 재배포 가능, 저작권 고지 유지) | 확인 |
| 각 TTS 모델 가중치 | 모델마다 다름 | 미검증 |

중요: 앱이 MIT 라이선스라고 해서 앱이 내려받는 모델까지 MIT인 것은 아닙니다. 상업 채널이나 고객사 납품에 쓰기 전에, Hugging Face의 각 모델 페이지(Qwen3-TTS, Chatterbox 등)에서 라이선스를 직접 확인해야 합니다. 이 검토 환경에서는 Hugging Face 접속이 차단되어 확인하지 못했습니다.

## 7. 법적 위험과 대응

| 근거 | 내용 | 대응 |
|---|---|---|
| 부정경쟁방지법 제2조제1호타목 | 국내에 널리 알려진 타인의 성명, 초상, **음성** 등을 영업을 위해 무단으로 사용하는 행위는 부정경쟁행위 | 유명인 음성 복제 금지. 일반인도 서면 동의 확보 |
| 인공지능 기본법 제31조제2항, 제3항 (2026-01-22 시행) | 생성형 AI 결과물에 그 사실을 표시해야 하고, 실제와 구분하기 어려운 가상의 음향은 이용자가 명확히 알 수 있게 고지 또는 표시 | 영상 설명란과 화면에 "AI 음성 사용" 표시 |
| 플랫폼 정책 | 유튜브 등은 실제처럼 보이는 합성 콘텐츠의 공개를 요구 | 업로드 시 합성 콘텐츠 항목 체크 |

법령 원문은 국가법령정보센터 데이터로 확인했습니다. 인공지능 기본법상 표시 의무의 주체는 "인공지능사업자"이므로, 개인 채널 운영자가 해당하는지는 시행령과 해석에 따라 달라질 수 있습니다. 다만 표시하는 데 드는 비용이 거의 없으므로 일률적으로 표시하는 것을 권고합니다. 이 판단은 법률 자문이 아닙니다.

이 저장소의 클라이언트는 `clone` 명령에 `--i-have-consent` 옵션이 없으면 실행을 거부하도록 만들어, 동의 확인을 빠뜨리는 실수를 막습니다.

## 8. 기타 위험

1. **성능**: 1.7B 모델을 CPU로 돌리면 문장 하나에 수십 초 이상 걸릴 수 있습니다. 대안은 0.6B 모델 사용, Apple Silicon Mac에서 데스크톱 앱 사용(MLX 가속), NVIDIA GPU 사용입니다.
2. **첫 실행 지연**: 모델을 처음 쓸 때 수 GB를 내려받습니다. 클라이언트의 기본 대기 시간은 30분입니다.
3. **보안**: API에 인증 기능이 없습니다. 이 저장소의 Docker 구성은 `127.0.0.1`에만 열어 두었으며, 외부에 노출하면 안 됩니다.
4. **버전 변동**: 0.x 버전이므로 API가 바뀔 수 있습니다. Docker 구성은 검증한 커밋(`deploy/UPSTREAM_COMMIT`)으로 고정했고, 갱신할 때는 커밋 값을 바꾼 뒤 클라이언트 테스트를 다시 실행합니다.
5. **Linux 설치 파일 부재**: Linux에서는 Docker 구성을 사용합니다.

## 9. 도입 방안 (이 저장소에 구현된 내용)

| 단계 | 내용 | 위치 |
|---|---|---|
| 1. 검토 | 본 보고서 | `docs/01-기술검토.md` |
| 2. 업무 연동 | 한국어 내레이션 CLI(대본을 문단별 WAV로 일괄 생성, 이어서 생성 지원), Claude Code MCP 설정 | `client/`, `mcp/` |
| 3. 한국어 운영 구성 | 업스트림 코드를 포크하지 않고, 고정 커밋으로 받아 빌드하는 Docker 구성과 한국어 기본값(소희 프리셋, `ko`, 한국어 미지원 엔진 차단) | `deploy/`, `client/` |

3단계를 원본 포크 대신 이런 구성으로 만든 이유는, 포크하면 업스트림이 바뀔 때마다 직접 병합해야 하기 때문입니다. 지금 필요한 한국어 기본값은 API 호출만으로 설정할 수 있어 원본 코드를 수정할 필요가 없었습니다. 원본 코드를 고쳐야 하는 요구(예: 한국어 숫자 읽기 전처리를 서버에 내장)가 생기면 그때 포크를 검토합니다.
